# Security Policy

Report vulnerabilities that could permit code execution, dependency compromise, workflow tampering, policy bypass, forged evidence, unauthorized mutation, or release-artifact substitution privately through GitHub's private vulnerability reporting feature when available, or through the public contact information on the maintainer's GitHub profile.

Policy disagreements, schema defects without security impact, incorrect documentation, and mathematical errors in governed projects should use the appropriate public issue template.

Include affected versions or commits, reproduction steps, impact, and proposed mitigation. Cruthúnas has not yet published a stable framework release, and no response-time guarantee is currently offered.
